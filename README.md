# 放映室 · Private Screening

**中文** · [English](README.en.md)

把自己家的 NAS 变成一间私人影院：影视、电视直播、音乐收进同一个界面，跑在你自己的机器上，同一份前端也能装进电视和手机。

搜片名 → 点开 → 直接播。主页只留内容，片源与下载都在控制台里管理。

- 当前版本 **0.13.0**（Android TV / 手机 / Web 三端同源）
- **零内置内容源**：不带任何片源、直播列表、音乐接口，装完是空壳，配置由你自己提供
- 零构建前端，`python3 app.py` 即开即用，不需要 pip、Node、打包
- NAS 关机后 App 仍可独立搜索、看详情、播放

## 功能

一句话版：**内容直连采集站，NAS 只管配置、同步、投屏桥接和升级。**

### 影视

| 能力 | 说明 |
|---|---|
| 聚合搜索 | 一次同时问全部片源，同一部片自动合并，列出全部线路 |
| 多线路播放 | 每条线路标出画质（4K / 1080P / 720P / HD），播不动自动换下一条 |
| 剧集连载 | 按集排列，换线路不丢进度，一集播完自动接下一集 |
| 片库浏览 | 电影 / 剧集 / 动漫 / 综艺 / 纪录片分栏，按年份、地区、单源筛选 |
| 片源管理 | TVBox 配置地址一键导入、优先级排序、单个测试、开关（Web） |
| 下载 | 接自己的 qBittorrent，磁力搜索结果带做种数，一键提交（Web） |

### 电视直播

| 能力 | 说明 |
|---|---|
| 导入与分组 | M3U / TXT 导入，自动分组，同名频道合并多线路 |
| 探活 | 一键检测可用；失效的压暗保留，不悄悄删掉 |
| 每日汇总 | 每天把候选源全拉一遍 → 合并去重 → 逐条探活 → 只留能播的 |
| 维护 | 分组查看、手动刷新、批量探活（Web） |

### 音乐

| 能力 | 说明 |
|---|---|
| 曲库 | 本地目录 ID3 / FLAC、Subsonic 兼容服务（Navidrome / Airsonic / Gonic）、在线歌单 |
| 发现 | 推荐歌单、分类歌单（主题 · 语种 · 风格 · 场景 · 情感）、专辑墙、歌手、在线搜歌 |
| 播放 | 队列、循环模式、滚动歌词、粒子进度条、播放模式记忆 |
| 音效 | Web 是 10 段均衡器 + 8 组预设；电视的音效预设按设备频段自动适配 |

三端都有音乐，播放器按输入方式各做一套：手机是黑胶 + 逐行歌词、播放条常驻任意 tab；电视是左唱片右歌词、遥控器上下切歌左右调进度。

### 播放器

| 能力 | 说明 |
|---|---|
| 手势与遥控器 | 单击暂停 / 播放，双击全屏；电视用方向键移动焦点、回车确认、BACK 返回 |
| 断点续播 | 进度每几秒记一次，下次从停下的地方继续 |
| 缓冲态 | 模糊海报 + 三个跳动波点 + 实时网速，不转圈 |
| 画中画 | 开小窗可继续浏览、搜索、换片，关窗即结束 |

### 投屏

手机点一下就把片子交给电视，自己随即变成遥控器。电视端是**真的接收端**——原地起播、真实进度回报，而不是把手机画面镜像过去。

三条通道，谁连得上就走谁，能力不同按键自动置灰：

| 通道 | 怎么连 | 能干什么 |
|---|---|---|
| NAS 中转 | 两端都连 NAS，走 `/api/cast/*` 名录 | 全功能：倍速、音量、进度回读；不在同一网段也能投 |
| 局域网直投 | 自研 `PROOM-CAST/1`，UDP 广播发现 + JSON over HTTP | 全功能；不经过 NAS，NAS 关着也能用 |
| DLNA | 电视当标准 MediaRenderer（AVTransport） | 只有播放 / 暂停 / 拖动 / 停止，倍速与音量灰掉，也读不到电视播到第几秒 |

SSDP 被路由拦掉时还有两条兜底：扫码直连（电视显示二维码与配对码，手机扫一下就知道往哪投）和手动填地址。

### 管理与备份

| 能力 | 说明 |
|---|---|
| 配置备份 | 导出完整配置或只要片源；导入有预览，写前自动备份，可回滚 |
| 配置分享 | 片源、直播源、音乐与界面偏好打包成一个 JSON，可导出导入 |
| 配置分发 | NAS 只发配置包，App 启动后台静默更新，内容没变就不重绘 |
| 下载任务 | 暂停 / 继续 / 删除，状态自动刷新 |
| 关于与自检 | 后端连通性、片源可用性、版本信息一览 |
| 内网自升级 | App 启动查 `/api/app/latest`，有新版本就提示并拉起系统安装器 |

### 独立运行

| 能力 | 说明 |
|---|---|
| App 独立运行 | NAS 关机也能搜、看、播，配置停在最后一次同步的版本 |
| 无账户 | 打开即用，没有登录、没有 PIN（`NO_AUTH=1` 默认） |
| 本地缓存 | 页面数据与影片索引存本地，先渲染再拉新，界面不跳 |
| 零第三方依赖 | 前端零构建、字体自托管、不引用任何 CDN |

## 三端

三端不是"同一套界面的放大缩小版"，每一端的输入设备和观看距离决定了交互规则。

| | PC 浏览器 | 手机 App | 电视 App |
|---|---|---|---|
| 包名 | —（浏览器直接访问） | `com.projectionroom.app` | `com.projectionroom.tv` |
| 定位 | **管理台 + 消费端** | **随身消费端** | **大屏消费端** |
| 输入 | 键鼠 | 触摸 | 遥控器 |
| 浏览 / 搜索 / 播放 | ✅ | ✅ | ✅ |
| 收藏 / 播放记录 | ✅ | ✅ | ✅ |
| 音乐 | ✅ 完整 | ✅ 完整 | ✅ 完整（含音效预设） |
| 投屏 | 接收端控制 | ✅ 发射端 | 接收端 |
| 片源 / 直播源 / 下载 / 备份 | ✅ 全部入口 | ❌ 不提供 | ❌ 不提供 |

### PC 浏览器（管理台）

打开 `http://<nas>:8899` 就是最新版，不装任何东西。

- **全部**：影视、直播、音乐、搜索、播放、投屏
- **管理一切**：片源导入与排序、直播源维护、下载任务、配置备份
- 宽屏有版心，不会把内容拉得又扁又长；375 到 3840 全覆盖

![首页](docs/screenshot-home.png)

随身携带的消费端。**没有「设置」这一层**：所有会改服务器数据的事都在 PC 上做，手机只负责读配置和使用。

- 底部四个 tab：影视 / 直播 / 音乐 / 我的
- 「我的」把收藏和播放记录合并在一起，一屏看完
- 播放页同一套手势：单击暂停、双击全屏
- 投屏时手机就是遥控器：进度、音量、倍速、选集、换源全在手上

### 电视 App

10-foot UI，遥控器是唯一输入。规则和手机端**刻意不同**：

- **返回只认遥控器 BACK 键**，页面上没有可聚焦的返回按钮（那会在用户往左上移动的路上埋一个「一按就退出」的坑，还会抢初始焦点）
- **初始焦点永远落在第一个可操作内容上**（第一张卡 / 主按钮），不落在导航控件上
- **不放锁 / 画中画 / 投屏**：电视是接收端，投屏只能投自己；系统不支持 PiP；锁屏是防手指误触，而电视没有触摸
- **氛围背景不依赖 `Modifier.blur`**：它在 API 31 以下是空操作，而电视盒子一大半跑在 28~30，统一走 `SoftBackdrop`（小尺寸解码 + GPU 放大），任何 API 上都是同一种软色雾

## 架构

一句话：**NAS 是「配置分发 + UI 更新」的服务器，不是运行时。**

```
┌──────────────── NAS（可关） ────────────────┐
│ /api/config/bundle   片源清单 + 直播频道表   │
│ /api/app/latest      APK 版本               │
│ /static/**           网页版（给 PC 用）      │
└─────────────────────────────────────────────┘
              │ 启动时后台拉一次，存本地
              ▼
┌──────────── 手机 / 电视 App（独立运行时） ────┐
│ 内置前端 + 本地 HTTP 服务（127.0.0.1）        │
│ 本地聚合：直接问源站（/__fetch 原生代发，绕过 CORS）│
│ 本地缓存：IndexedDB 存页面数据、影片索引       │
│ 本地媒体代理：补 Referer / 重写 m3u8           │
└─────────────────────────────────────────────┘
```

于是：

- **NAS 关掉**，App 照样搜索、看详情、播放；只是配置停留在上一次同步的版本
- **NAS 开着**，启动后后台静默更新配置，**界面不会跳**（内容没变就不重绘）
- **PC** 打开 `http://<nas>:8899` 用的就是最新版，不装任何东西

服务端只保留四类接口：**同步**（收藏、历史、片库索引）、**投射**（投屏桥接）、**更新**（版本检查与 APK 下载）、**配置**（配置包与直播频道表）。首页、片库、搜索、详情、线路解析、播放、封面图全部由客户端直连源站，不走 NAS 兜底。

技术上由 `static/app/core/platform.js` 一处判定（UA 里的 `ProomTV/`、`ProomPhone/`），管理入口带 `data-admin-only` 属性，App 启动时整体移除。

设计演进见 [`docs/standalone-arch.md`](docs/standalone-arch.md)。

## 快速开始

### 直接运行

```bash
git clone https://github.com/saury91/nas-screening.git
cd nas-screening
python3 app.py
```

打开 `http://127.0.0.1:8899`。第一次启动会自动建库，首页推荐需要十几秒预热。

> 不需要 pip，也不需要装 Node、跑打包。

### Docker

```bash
docker build -t projection-room .

docker run -d --name projection-room --restart unless-stopped --network host \
  -e DB_PATH=/data/media.db \
  -v /你的数据目录:/data \
  projection-room
```

接 qBittorrent 和本地音乐目录：

```bash
docker run -d --name projection-room --restart unless-stopped --network host \
  -e DB_PATH=/data/media.db \
  -e QBT_URL=http://127.0.0.1:8080 \
  -e QBT_USER=<用户名> \
  -e QBT_PASS=<密码> \
  -e MUSIC_DIR=/music \
  -v /你的数据目录:/data \
  -v /你的音乐目录:/music:ro \
  projection-room
```

### 第一次打开：空壳是正常的

**仓库不自带任何内容源**：没有片源、没有频道、没有音乐接口、没有磁力站。
装完打开就是空壳，页面会显示「还没有片源」，这是设计如此，不是装坏了。

配好数据源之前它不会去找任何第三方地址。按这个顺序来：

1. **不要把 8899 直接暴露到公网**：默认无鉴权，只应是内网服务；要外网访问请加反向代理鉴权。
2. **导入片源**：控制台 → 片源管理。粘贴一份 TVBox 配置地址批量导入（见下面的「数据源自备」）。
3. **导入直播**：控制台 → 直播源。填候选源地址，之后每天自动重新抓取、合并、探活。
4. **接音乐**（可选）：本地目录或 Navidrome / Airsonic / Gonic；在线歌单与在线搜歌需要自己填接口。

### 数据源自备

仓库里没有任何采集站地址、直播列表、音乐接口。三种方式把自己的数据装进来：

| 方式 | 做法 | 适合 |
|---|---|---|
| 配置包 | 控制台 → 配置备份 → 导入，选一个 JSON | 从别的机器搬过来 |
| 手动填 | 片源管理里逐条加，或粘 TVBox 配置地址 | 只加几个 |
| seed 文件 | 把导出的 `seed.json` 放到 `data/seed.json` 再启动 | 一次装好整套 |

`data/seed.json` 是首启播种文件，格式与配置包一致：

```bash
# 从当前库导出（里面是真实地址，只留在本地）
python3 tools/export-seed.py                 # → data/seed.json

# 换台机器：把文件拷过去，放在同样位置，启动即自动写入
DB_PATH=/data/media.db SEED_FILE=/data/seed.json python3 app.py
```

`data/` 整个目录都在 `.gitignore` 里，导出的文件不会被提交。想换路径用 `SEED_FILE` 指定。

只有 seed 文件存在**且**对应表为空时才播种；之后完全以数据库为准，删掉的源不会因为重启又被写回来。

### 装到电视 / 手机

```bash
cd native
./gradlew :app-tv:assembleDebug      # 电视：native/app-tv/build/outputs/apk/debug/
./gradlew :app-phone:assembleDebug   # 手机：native/app-phone/build/outputs/apk/debug/
adb install -r <apk 路径>
```

JDK 17（Gradle 8.10.2 配 JDK 27 会直接报错），compileSdk 35。

**签名与升级**：APK 用固定密钥签名（`native/keystore/proom.jks`，密码 `proom-release`），
签名必须一致才能覆盖安装，所以这份密钥跟着仓库走，保证谁构建都是同一条升级链。
它只保证升级不被「签名不一致」挡住，不提供安全强度：密钥是公开的。
想更稳妥就在 CI/本地用 `PROOM_KEYSTORE`、`PROOM_KEYSTORE_PASS` 换成你自己的。

TV 第一次装需要允许「安装未知应用」；国产 ROM 会弹「未备案/风险应用」提示，勾选「已了解风险」继续即可。

## 运行参数

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8899` | 监听端口 |
| `DB_PATH` | `./data/media.db` | 数据文件位置，容器里建议指向挂载卷 |
| `SEED_FILE` | `./data/seed.json` | 首启播种文件；不存在就空启动 |
| `LIVE_SEEDS` | 空 | 直播候选源，逗号分隔，每日自动汇总用 |
| `CMS_SEEDS` | 空 | 片源「资源目录」地址，逗号分隔，自动发现用 |
| `MUSIC_ONLINE` | `0` | 为 `1` 时启用在线搜歌（直连第三方音乐接口） |
| `MUSICBOX_API` | 空 | 在线歌单/播放接口地址，空即关闭在线音乐 |
| `MUSICBOX_REFERER` | 空 | 上面那个接口要求的 Referer |
| `MAGNET_SITE` | 空 | 磁力搜索站地址，空即关闭磁力搜索 |
| `MUSIC_DIR` | 空 | 本地音乐目录，也可以之后在设置页里填 |
| `QBT_URL` | `http://127.0.0.1:8080` | qBittorrent 地址 |
| `QBT_USER` / `QBT_PASS` | 空 | 只通过环境变量传入，代码里没有默认凭据 |
| `NO_AUTH` | `1` | 为 `0` 时启用多账户（每人一份记录与收藏） |

带「空即关闭」的几项是内容入口：不填就不会向任何第三方服务发请求。

> 这是**内网**方案：没有密码、没有 HTTPS。不要把 8899 直接暴露到公网；
> 真要外网访问，请在反向代理上加一层真正的鉴权。

```bash
python3 -m unittest discover -s tests -v     # 纯函数单测
cd native && ./gradlew :core:jvmTest         # 数据层单测
cd native && ./gradlew :app-tv:assembleDebug # 编译即校验
```

CI 两个 workflow：

| 文件 | 触发 | 做什么 |
|---|---|---|
| `ci.yml` | push / PR | Python 编译 + 单测 + 前端 ESM 语法检查 |
| `native.yml` | `native/**` 变更 | 数据层单测 + 编译两个 debug APK，产物上传 Artifact |

发版走一条命令：

```bash
cd native && ./gradlew :app-tv:assembleRelease :app-phone:assembleRelease
cd .. && ./tools/publish-apk.sh tv && ./tools/publish-apk.sh phone
```

`publish-apk.sh` 会把 APK 和 `{versionCode, versionName, size, sha256, notes}` 一起写进
`data/apps/`，App 端会校验 size 与 sha256，坏包不会进安装器。

## 约定

改代码前先看这几条：

1. **缓存优先**：页面数据先读本地（IndexedDB）立刻渲染，后台再拉新；新旧内容一样就不重绘。
2. **不提示「离线」**：连不上 NAS 是常态，安静用缓存即可，界面上没有「离线模式」这种东西。
3. **大媒体直连 NAS**：音频/大文件不走本地代理（会被整块缓冲拖死）；小分片和需要 Referer 的走本地代理。
4. **本地代理只做三件事**：静态资源、`/api/*` 反代、`/__fetch` 代发（绕 CORS）。
5. **视频显影看状态不看事件**：`readyState>=2 && videoWidth>0` 才显示，否则直播/切源会「有声无画」。
6. **服务端不保存运行时状态**：NAS 只提供配置、直播表、APK 版本与网页版。
7. **每一端遵守自己的输入规则**：电视只认遥控器、手机只认触摸，不要为了「一致」把 PC 那套搬过去。
