# 电视端焦点交互规范 v2 · 边框发泡

> v1 曾提议"统一白色外圈"，实测不够优雅：凭空多一圈硬线，像画了个框。
> v2 改为：**不套圈、不改色，让组件自己的边框鼓起来。**

## 1. 规则

聚焦时改三件事，其余都不动：

1. **画一圈白色锐环**：2dp，内沿离元素边缘 2dp，与元素同形（不是缩放出来的方框）
2. **垫一圈极淡黑衬**：10% 黑、3 倍环宽，只向外长，给白环在亮画面上托底
3. **整体微胀**：仅网格卡片用（1.04）。按钮、圆键、tab 不缩放 —— 环已经往外鼓了 3dp，
   再整体放大就是把「鼓」画两遍；「立即播放」离收藏钮只有 12dp，放大后的环正好压到那颗心形上

焦点环恒为白色，不跟着组件的底色走；元素自身的边框色（金 / 中性）只表达「它是谁」，**不参与焦点**。

## 2. 「选中」与「聚焦」的区分

**颜色不承担语义**：焦点环永远是白色，选中态永远是品牌金。屏幕上只出现两种强调，靠「各管一件事」分开，不靠谁更亮：

| | 选中 | 聚焦 |
|---|---|---|
| 颜色 | 品牌金（金底 / 金边） | 纯白（一圈白环） |
| 描边位置 | 内侧 1.5dp，静态 | 卡片外扩 3dp / 密集行内收 2dp |
| 暗衬 | 无 | 10% 黑，只向外 |
| 缩放 | 1.00 | 1.04（行 / chip 保持 1.00） |
| 动效 | 静止 | 220ms 弹性 + 3% 过冲 |
| 语义 | 这是当前项（状态） | 遥控器停在这（位置） |

叠加时：内层金线固定不动，外层白环鼓起 —— "内金外白"，一眼分得开。

**两种做废的写法（都在真机上翻过车）：**

1. **焦点环用金色**：金环与金底选中项同屏，用户分不清「停在这」和「就是当前项」；首页一堆按钮有的白有的金，看起来就是没做完。
2. **聚焦时把底色翻白**（详情页「立即播放」、首页 hero 主按钮、歌单页「全部播放」都这么干过）：白环贴在自己的白底上等于没有，于是白底又得配金环 —— 颜色语义彻底打架，还和「底金 = 主操作」冲突。

结论：**底色只表达「这是什么」**（主操作 = 金、普通 = 深灰/白），**焦点只表达「停在哪」**（白环 + 光晕）。任何控件都不许因为聚焦而改底色色相；提亮同一色相（surface → surface2）可以。

## 3. Token

| 属性 | 静息 → 聚焦 | 说明 |
|---|---|---|
| 边框宽 · 卡片 / 圆形键 | `1 dp → 3 dp` | 朝外生长，不改内部布局 |
| 边框宽 · 行 / chip / 输入框 | `1 dp → 2 dp` | 密集排列，3dp 会与邻项顶住 |
| 外扩 | `0 → 2 dp` | 环内沿离元素边缘的缝隙 |
| 暗衬 | 黑色 `10%`，宽 3×环宽 | 只向外长，亮画面里托住白环，深色页面里看不见 |
| 白柔光 | **不用**（见 4.1 ④） | 深色底上必然形成第二条线 |
| 缩放 | `1.000 → 1.040`（主键 1.06） | 行 / 弹窗项保持 1.000 |
| 进入缓动 | `spring(dampingRatio .58, stiffness 380)` | 约 220ms，带 3% 过冲 |
| 离开缓动 | `160 ms` 线性，无过冲 | 离场要干脆 |

**环色默认就是 `Color.White`**，调用方不要传 `color`，除非该处确实需要（目前全仓为零处）。
金色绝不进焦点环 —— 那是「选中」的语言（见 §2）。

## 4. 五种状态

| 状态 | 画法 |
|---|---|
| ① 默认 | 1dp 边框（`line` 或组件自有色），无光晕，缩放 1 |
| ② 聚焦 | 白色锐环 2dp（外扩，与元素同形）+ 极淡黑衬；不叠白色柔光 |
| ③ 选中 | 内描边 1.5dp + 金底 14%，静止 |
| ④ 选中＋聚焦 | 只留 ②，把 ③ 的描边撤掉（见 4.1） |
| ⑤ 禁用 | 36% 不透明，可聚焦但不发泡、不响应 |

### 4.1 两条不许破的底线

**① 环不许压在内容上。** 环的偏移是「环宽/2 + 2dp」，`inset = true` 时这 3dp 是从元素内部扣的。
线路卡、集数格这种「序号贴着左边、集数贴着底部」的小格子，一内收就会穿过文字 ——
截图里「18」被白环劈开，看着像描边画歪了。**格子之间只要还剩 ≥ 8dp 缝，一律外扩。**

**② 选中和聚焦不叠两个框。** 一个元素同时是「当前项」又是「光标」时，
金边 + 白环 = 两个控件粘在一起。做法：聚焦时撤掉选中描边，选中语义交给底色和文字颜色。
顶栏 tab 更进一步 —— 选中态从「金块」换成「金字 + 底部金线」：
金块 + 白环同屏时，顶栏上一排有两个「按下去」的东西，分不清哪个是位置、哪个是光标。

**③ 环必须和元素同形，不许靠 `scale()` 放大。**
`graphicsLayer` 的缩放是各算一个系数：130dp×54dp 的按钮是 1.05 / 1.15，
圆角矩形被非等比拉伸后圆角变成椭圆角、竖边比横边粗 —— 屏幕上就是「一圈方框套着圆角按钮」，
观众看到的是「描边画歪了」而不是「这个按钮被选中了」。

**④ 深色界面上不要白色柔光，只要一圈锐环 + 极淡黑衬。**
用多层同心描边模拟外发光这条走了很久，结论是行不通：
16% 的白落在 `#000` 上是 `#292929`，紧挨着 100% 的白环，屏幕上就是**第二条线**。
观众数出来的是「两个框」，而不是「一个发光的框」。层数减到 2 层只是把第二条线变淡，不会消失。
而且宽描边以轮廓线为轴左右各长一半：3dp 的缝里塞一条 7dp 的柔光，有 3.5dp 直接盖在按钮上，
金色底边被蒙成灰的 —— 这就是「按钮看着脏」的来源。
现在的画法：每一层用自己的轮廓 + 自己的平移，内沿统一钉在「元素边缘外 2dp」，
只朝远离元素的方向长；白色只留 1dp 锐环，外面垫一圈 10% 的黑衬（亮画面里托住白环，深色页面里看不见）。
正确做法：按 `size + gap*2` 重新 `createOutline`，再 `translate(-gap, -gap)` 画，
圆角半径和描边粗细各处一致。

## 6. 行为规则（不变）

1. 进页面必落焦第一个可交互项；空态落在「重试 / 返回」。
2. 切 tab、弹窗开关、列表刷新后显式 `requestFocus` 并重试 2~3 次（Compose 焦点树重建期会"假成功"）。
3. 聚焦项离滚动边缘 ≥ 48dp，发泡外扩部分也要算进去，不能被顶栏裁掉。
4. 控制条 3 秒无操作收起，焦点回播放键；焦点移动重置计时。
5. 弹窗打开聚焦首个按钮，关闭后还给触发元素。
6. 每屏都要有可见、可聚焦的返回项，不能只靠系统 Back。

## 7. 实现方案（Compose）

统一入口，替代 26 处手写焦点：

```kotlin
// 需要自己监听焦点时
Modifier.tvFocusRing(shape = RoundedCornerShape(ProomShape.md), ringWidth = 2.dp, zoom = 1f)
// 组件已经知道 focused、只是要画出来时（避免重复注册焦点监听）
Modifier.tvFocusBloom(shape, bloom, ringWidth = 2.dp, color = Color.White, inset = false)
```

内部要点：

- `bloom` 是 0~1 的展开进度，由 `animateFloatAsState` 驱动：进 `spring(0.52f, 420f)`，出 `tween(150)`。
- 绘制必须放 `drawWithContent`（先 `drawContent()` 再画环）：行类元素有 `bgSoft` 底色，`drawBehind` 画的环会被自己的背景整块盖掉。
- 每层环都按「自己的尺寸 `createOutline` + 自己的 `translate`」画，**不要**共用一个轮廓再加宽描边 —— 加宽描边会往元素内部压一半（见 4.1 ④）。
- 不用 `BlurMaskFilter` / `RenderEffect`：TV 盒子 GPU 弱，每帧重建模糊会掉帧；而现在只有一圈锐环，本来也不需要模糊。
- 环画在 `clip` 之外，避免被 `clipToBounds` 切平。
- 缩放用 `graphicsLayer`，不触发重组；透明度变化只走绘制，不重建子树。

## 10. 真机验证（Android TV，1920×1080 @320dpi，`android-tv` 镜像）

CSS 稿上成立、真机上翻车的三处，已全部修正并写入实现约束：

| 问题 | 现象 | 约束 |
|---|---|---|
| 环的空间不够 | 设置行上下紧贴堆叠，外扩环被相邻行的不透明底色吃掉，整行只剩**一条底边**露在缝里 | 行类元素一律 `inset = true`，环压进行内 padding；卡片才外扩 |
| 环被自身背景盖住 | 行有 `bgSoft` 底色，`drawBehind` 先画、背景后画，内收环被整块盖掉，屏幕上什么都不剩 | `tvFocusBloom` 用 `drawWithContent`（先画内容、再画环），不能用 `drawBehind` |
| 「金块镶白边」 | 描边中心线压在元素边界上，一半环陷进内容里，金底 tab 上糊成一坨 | 偏移量 = `环宽/2 + 2dp`，只让半个环宽以外的那 2dp 成为缝隙 |
| 浅底吞环 | 播放主按钮、详情页「立即播放」曾经在聚焦时整块翻成白底，白环贴上去几乎看不见，只剩一圈深缝 | **底色不许因为聚焦而翻白**：主按钮恒定金底，聚焦只加白环（金环会跟「选中」打架，见 §2） |

另外两条真机结论：

- **不用真模糊**。`BlurMaskFilter` 每帧重建会掉帧，TV 盒子上零开销的做法只有实心描边。
- **但也不要多层同心描边模拟柔光**。宽度 ×1/2.2/3.6/5.6/8.2、alpha 1/.30/.16/.075/.03 这一套在截图放大后能数出三条线，
  观众看到的是「两个框」；而且宽描边往内压 3.5dp，把金色按钮的边蒙灰（详见 4.1 ④）。现在只有 1dp 白环 + 1 层黑衬。
- **1/3 缩放可辨性测试通过**。把截图缩到 620px 宽（模拟 3 米看电视）后，锐环仍然清晰；证明"看得见焦点"靠的是那圈实环，
  光晕既不能反过来依赖，也补不上环本身的形状问题。

设备注意：`tv1080` 这个 AVD 的 `tag.id=default`，是**手机系统镜像跑 TV 分辨率**，没有 `leanback`，D-pad 与焦点行为都不对；验证必须用 `tv33`（`android-tv`）。

### 10.1 浮层（面板）里的焦点

面板是最容易"改造完看不出来"的地方 —— 环本身画对了，但焦点根本进不去，屏幕上一片安静。三个坑：

| 问题 | 现象 | 约束 |
|---|---|---|
| 环排在 `clip` 之后 | 播放设置面板的 `SideChip` 完全看不到环，只有按钮左下角漏出一点点弧 | 修饰符顺序固定 `tvFocusRing` → `clip` → `background`。环在 `clip` 之后会被自身圆角裁掉，但不会报错 |
| `focusRequester` 挂在链尾 | `requestFocus()` 不抛异常、也拿不到焦点；`runCatching` 一吞，排查时以为"请求成功了" | 一律放在可聚焦修饰符**之前**：`modifier.focusRequester(first).tvFocusRing(...).clickable(...)` |
| 遮罩层可聚焦 | 遮罩用 `clickable` 吃点击后，遥控器往边上按会掉进这一整屏的"隐形按钮"，怎么按都没反应 | 遮罩只吃触摸：`Modifier.pointerInput(Unit) { detectTapGestures { } }`；关面板只认 ✕ / 返回键 |

配套两条实现约定：

- 每个浮层都调 `rememberSheetFirstFocus()`（`PlayerScreen.kt`）：连续 10 × 100ms 重试。面板是刚组合出来的新子树，前一两帧还没挂进焦点树，单次请求常常静默失败。
- 浮层根 `Column` 加 `Modifier.focusGroup()`，方向键在面板内自成一圈，不会从最上面一行跳到背后控制条的按钮上。

回归验证的落点（`tv33`）：播放设置面板首焦点在「关闭」行、下移逐行滚动；睡眠定时首焦点「15 分钟」；投屏面板首焦点 ✕、下移落到设备行。

### 10.2 批量改造的教训

用脚本批量替换 66 处焦点时，脚本把 `.clip(` 行替换成了 `.tvFocusRing(`，造成两类破坏：

- 同一修饰符链里出现两次 `tvFocusRing`（环画两遍，性能翻倍且视觉上叠成实心）；
- `clip` 丢失，圆角外漏。

清理方式：按「相邻两行都是 `tvFocusRing`」「`clip` 之后 3 行内出现 `tvFocusRing`」两条规则全仓扫描，再逐处手工重排。**批量脚本只适合定位，不适合直接写修饰符链。**

### 10.3 面板里的 ✕ 要能按到

面板的 ✕ 在标题行右侧，和下面那列行不在同一条轴上，Compose 的一维焦点搜索（`focusGroup` 内按几何就近取）找不到它 —— 遥控器无论怎么按都停在行列表里，只能按返回键关面板。

显式接一条链就够，不用改版式：

```kotlin
val closeFocus = remember { FocusRequester() }
val firstFocus = rememberSheetFirstFocus()

// ✕
Modifier.focusRequester(closeFocus).focusProperties { down = firstFocus }
// 首行
Modifier.focusProperties { up = closeFocus }.focusRequester(firstFocus)
```

`FocusProperties.up / down` 接受 `FocusRequester`，两头都接上才是双向的；只接一头会出现「上得去、下不来」。

顺带：`focusGroup()` 只保证方向键优先在组内找目标，**不保证一维列里的每一行都能横向走到旁边的控件**。凡是「位置上突兀」的焦点目标（✕、右上角图标、跨列按钮），都按上面这套显式接。

### 10.4 播放器页焦点清单（核对基线）

播放器是最容易漏的一块：控件散在控制条、投屏条、四个面板里，且都带「状态色」（金色主键、青色投屏键、红色停止），一不留神就把状态色当成了焦点色。

**控制条**

| 控件 | 底色（是什么） | 焦点（停在哪） |
|---|---|---|
| 上一集 / 下一集 | 黑 0.30 圆 + 1dp 白 0.10 细边 | 白环**外扩** 2dp |
| 播放 / 暂停 | **恒定金**（主操作），64dp | 白环**外扩** 2dp（内收会在金圆上压成一圈「甜甜圈」） |
| 跳过片头 | 金 0.18 半透明胶囊、金字，44dp 高，无描边 | 白环**外扩** 2dp |
| 倍速 / 定时 / 字幕音轨 / 信息 / 选集线路 | 黑 0.30 圆 + 1dp 白 0.10 细边，52dp | 白环**外扩** 2dp |
| 进度条手柄 | 白点 | 白晕 + **深缝** + 白环（描边），走 Canvas，不是 `tvFocusRing` |
| 播放设置抽屉 ✕ | 无底 | 白环；↓ 回当前线路格，tab 行 ↑ 到 ✕ |

**控制条布局：三组绝对定位，播放键钉死屏幕中点**

```kotlin
Box(Modifier.fillMaxWidth().height(80.dp)) {
    Row(Modifier.align(Alignment.CenterStart))  // 时间码 + 跳过片头
    Row(Modifier.align(Alignment.Center))       // 上一集 / 播放 / 下一集
    Row(Modifier.align(Alignment.CenterEnd))    // 倍速 / 定时 / 字幕音轨 / 信息 / 更多
}
```

曾经是一条 `Row` + 左右两个 `weight(1f)`：左侧只有一个时间码，右侧塞 6 颗按钮，重量差一倍多，
播放键被顶到偏左半屏，整条控制层看着是歪的。**判定标准：主操作必须落在屏幕几何中心，与两侧内容多少无关。**

同理，「跳过片头」跟着时间码放左侧：它是个带文字的暖色药丸，混进右侧那排圆钮里会打断节奏，
而且片头区间一过它就消失，放在右侧会让整排按钮横向位移。

**焦点环与 `clip` 的先后顺序（踩过两次）**

`Modifier.tvFocusRing` 必须写在 `.clip()` **之前**，否则 `drawWithContent` 画在裁剪层内部，外扩部分被裁掉 ——
屏幕上只剩金圆，一个字都看不出「它被选中了」。写成
`.tvFocusRing(...).clip(...)` 后，环在裁剪层外的同级绘制，外扩才可见。

**投屏条（cast 模式）**：主键是青色渐变 —— 青色表示「正在投哪台设备」，不是焦点；焦点照样白环。曾经这颗按钮完全没有环，遥控器停上去屏幕毫无反应。

**面板**

| 面板 | 首焦点 | ✕ 可达 |
|---|---|---|
| 投屏 | ✕ | 是（首焦点本身就是 ✕） |
| 播放设置（抽屉） | 当前线路格 | 是（tab 行 ↑，✕ ↓ 回来） |
| 播放设置（Palette 行） | 行列表首行 | 无 ✕，靠返回 / 点遮罩 |
| 睡眠定时 | 「15 分钟」 | 无 ✕，靠返回 |
| 播放信息 | 字幕「关闭」行 | 是（chip 行 ↑ 到 ✕，✕ ↓ 回 chip 行） |

**两个反例（都已修）**

- 进度条原来聚焦是**金环 + 金光晕**，是全页最后一处金色焦点；
- 投屏面板「连接 / 停止投屏」是裸 `Text` 加 `clickable`，既没有环，命中区也只有字面大小。

**遮罩一律不许 `clickable`**

`PlayerPanel` / 睡眠 / 音乐页的三个面板都曾用 `clickable` 写遮罩，于是遮罩本身成了可聚焦节点：遥控器一旦落上去，屏幕上什么都看不见。统一改成：

```kotlin
.pointerInput(Unit) { detectTapGestures { onClose() } }
```

需要「拦点击但不关面板」时写 `detectTapGestures { }`（空 lambda）。判断标准：**能点、但不能被遥控器选中**。

**焦点不许改「内容色」，只许提亮**

金不只被禁止用在焦点环上，也不许出现在「因聚焦而变色」的文字/图标上。曾经散着 7 处 `color = if (focused) accent else …`：图标按钮、搜索放大镜、清空、正在播徽标、返回条。

现在一律写成「中性色 → 主文字色」：

```kotlin
val tint = if (focused) ProomColor.text else ProomColor.dim   // 而不是 accent
```

理由：屏幕上金色只该有两种出现方式 —— **金底 = 主操作**、**金底/金边 = 选中**。一旦图标也变金，用户看到金色就得先判断「这是选中还是光标」。

**白环需要一点暗衬**

焦点环是白的，而它经常站在深色 UI 上；但播放器控制条和音乐全屏页的环是站在**视频画面**上的，画面一亮（白墙、雪景）白环就没了底。`tvFocusBloom` 因此在最外层先画一圈 `3 × base`、`alpha 0.10` 的黑环：深色页面里看不出来，亮画面下刚好把白环托住。

**控制条自动收起后，必须留一个焦点落点**

电视上没有鼠标，`onPreviewKeyEvent` 只沿「焦点路径」下发。如果把整条控制层从组合里移除、又不把焦点交给任何人，屏幕上就没有任何焦点节点 —— 表现是：**6 秒后遥控器彻底失灵，只剩返回键能退出**。投屏接收页（`CastPlayerScreen`）就踩过这个坑：按时自动隐藏做对了，但没有落点，隐藏一次就再也唤不回来。

正确写法与点播播放器一致：

```kotlin
LaunchedEffect(showControls) {
    if (!showControls) runCatching { rootFocus.requestFocus() }   // 收到根节点
    else repeat(4) { delay(80); runCatching { playFocus.requestFocus() } } // 还给播放键
}

Box(
    Modifier.fillMaxSize()
        .focusRequester(rootFocus)
        .focusable()                      // 根节点自己必须可聚焦
        .onPreviewKeyEvent { e ->
            if (e.type != KeyEventType.KeyDown) return@onPreviewKeyEvent false
            val wasHidden = !showControls
            showControls = true
            tick++
            wasHidden                     // 只吞「唤出」那一下，其余必须放行
        }
)
```

最后一行最容易写错：控制条已经亮着时必须返回 `false`，否则方向键全被根节点吞掉，界面看着正常、按键毫无反应（`true`/`false` 写反过一次，整套方向键失效）。

**投屏接收页（`CastPlayerScreen`）**

这一屏是手机投屏时电视上出现的界面，属于电视端，焦点同样走白环：

- 播放主键底色恒为青色渐变（青色 = 投屏身份，不是焦点），聚焦加白环；
- 次级键（±10 秒、倍速、音量、退出）原来聚焦是 2dp **青色**描边，改成白环 + 底色提亮；
- 联调入口：`adb shell am start -n com.projectionroom.tv/.MainActivity -e screen castplay -e url <视频地址>`（`CastPlayActivity` 未导出，adb 直接起不来）。
