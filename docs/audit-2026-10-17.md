# 放映室 · 全量功能与体验审核报告

> 审核对象：`nas-screening`（commit `8ebb39b`）
> 审核范围：后端 `server/`、前端 `static/app/`、部署与工程化
> 重点：前端交互与氛围感
> 方式：完整代码通读 + 本地起服务实测（`DB_PATH=/tmp/pr-audit.db PORT=8991`）

## 0. 结论速览

**一句话**：这是一个"骨架非常正、细节已经打磨过一轮、但还差最后一公里"的项目。
分层清晰、零依赖的取舍很聪明，播放链路（HLS 同源代理 / 画质探测 / 画中画 / 空间焦点）已经超过同类玩具项目；
**真正的短板不是"再做功能"，而是三个"断裂"**：

1. **时间的断裂**——首屏要等 540KB 阻塞脚本，片库首点要等 26 秒，详情要等 4.5 秒；
2. **导航的断裂**——返回片库回到顶部且跳过第一页，Tab 键根本摸不到卡片，播放器和页面的视觉语言不是一套；
3. **氛围的断裂**——氛围层是写死的三套渐变，Hero 换片是硬切，进详情是整页重建，情绪接不上。

## 2. P0：必须优先处理（安全与正确性）

### 2.1 无鉴权 + 通配 CORS + 代理不拦私网 = 局域网里的"开放控制台"

三件事叠在一起才成为问题：

| 位置 | 现状 | 后果 |
|---|---|---|
| `server/api.py:75` | 所有响应 `ACAO: *` | 任意网页都能**读**你的观看记录、收藏、片源列表 |
| `server/api.py:180` | `OPTIONS` 允许 `*` 与方法/头 | 任意网页都能**发** POST：删片源、加磁力、改音乐密码配置 |
| `server/services/proxy.py:38` | 只拦 loopback / link-local / unspecified | `192.168.x.x`、`10.x`、`172.16/12` **可以代理**，等于提供内网探测与读取能力 |

也就是说：你访问一个恶意页面，它就能 `fetch('http://192.168.1.10:8899/api/sources/delete')`，
甚至借 `/api/proxy?u=http://192.168.1.1/...` 去摸路由器后台。

**建议（按成本从低到高）**

1. 默认 `HOST=127.0.0.1`，需要局域网访问时显式设置（改 `server/config.py:13`）；
2. CORS 改成同源：`Access-Control-Allow-Origin` 只在 `Origin` 与 `Host` 同源时回显，否则不下发；
3. 代理白名单化：补 `ip.is_private` 判断（但要允许你自己的采集站域名），或改成"只允许配置过的片源域名"；
4. 加一个可选 PIN：`X-Auth: <token>`，`pref` 里存哈希，中间件统一校验，前端首屏弹一次输入。

> 项目定位是局域网自用，第 1、2、3 条是必须的；第 4 条建议做，因为 NAS 上还挂着 qBittorrent 的删种能力。

### 2.2 片库回访会跳过第一页（真实 bug）

`static/app/pages/browse.js`

```js
// cacheSet 存的是"下一次要拉的页码"（第一页拉完后 st.pg 已经 +1 = 2）
cacheSet(bkey(), { items: st.items..., pg: st.pg, more: st.more });   // :254

// 回访时 hydrate 把 pg 恢复成 2，随后立刻 replace 拉第 2 页
function hydrate(cached){ ... st.pg = cached.pg || 2; }               // :26
await fetchPage(root, { replace: true, silent: true });              // :124
```

结果：**第二次进同一个分类，看到的是第 2 页的内容，第 1 页永远被跳过**，用户以为"片库少了 60 部"。

**修复**：`hydrate` 里固定 `st.pg = 1`（缓存只用于"先画出来"，不应该影响下一次请求的页码），
并且 `replace` 时要重置 `st.seen`（当前在 `fetchPage` 内重置，逻辑是对的）。

### 2.3 音乐搜索只搜了前 24 张专辑

`static/app/pages/music.js:65-70`：

```js
let albums = home.albums || [];          // home() 默认 limit=24
if (kw) albums = albums.filter(...);     // 纯前端过滤
```

后端明明有 `/api/music/search`（`api.js:63` 也包了 `musicSearch`），但**从未被调用**。
曲库超过 24 张专辑后，搜索就只剩"最近加入的 24 张里找"。

**修复**：输入框 debounce 后调 `api.musicSearch(kw)`，渲染专辑 + 单曲两组结果。

## 3. 前端交互与氛围感（本次重点）

### 3.1 氛围感：底子在，但缺少"随内容呼吸"

**现在做得好的**

- 全局 `.ambient` 三层径向渐变（暖金 + 冷蓝 + 底部反光），切页面时颜色会换（`base.css:51-69`）；
- Hero 有噪点层 `.hero-grain`、多层 `veil`、海报轻微倾斜 `rotate(.6deg)`，电影感是有的；
- 播放器缓冲用"模糊海报 + 三个波点 + 网速"，比转圈高级得多（`player.css:84-107`）；
- 详情页背景用 `mask-image` 让模糊海报在底部自然消失，而不是被硬切一刀（`pages.css:21-24`）——这个细节很讲究。

**关键问题：所有氛围都是"静态的、按页面写死的"**

| 现象 | 代码 | 影响 |
|---|---|---|
| 背景氛围只有 3 套（默认 / 音乐 / 直播），与当前影片无关 | `base.css:60-69` | 首页是《空门迷影》，背景却是固定暖橙，画面和氛围两层皮 |
| Hero 换片是**硬切**：改 `background-image` 无法过渡 | `hero.js:66` | 10 秒一次"啪"一下换图，破坏沉浸 |
| 页面切换是**先清空再淡入**，没有转场 | `main.js:52-54` | 卡片→详情是"消失再出现"，不是"长大" |
| 颗粒只在 Hero 里，其余页面是纯色 | `home.css:16` | 全局质感不统一 |
| 播放器出错/暂停后没有环境光，只有纯黑 | `player.css:10` | 电视上看是一块黑洞 |

**建议（按收益排序）**

**(a) 让氛围跟着海报走——一行 CSS 就能做到**

跨域图片不能用 canvas 取色（会污染画布），但**可以直接把海报当成背景图**，让浏览器自己模糊晕染：

```css
/* base.css：把当前片子的海报作为氛围光来源 */
.ambient{
  background-image:
    var(--ambient-poster, none),
    radial-gradient(900px 520px at 18% -10%, rgba(255,164,92,.16), transparent 65%);
  background-size: cover;
  filter: blur(90px) saturate(180%);
  opacity: .28;
  transform: scale(1.25);
}
```

```js
// home.js / detail.js / player.js 打开时设置一次
document.documentElement.style.setProperty('--ambient-poster', `url("${pic}")`);
```

效果：首页背景会随当前推荐影片变色，详情页会变成那部片的色调，播放器缓冲时有同色环境光。
不需要任何取色算法，也没有 CORS 问题。

**(b) Hero 交叉淡入 + 缓慢推镜**

```html
<div class="hero-bg" data-layer="a"></div>
<div class="hero-bg" data-layer="b"></div>
```

```js
function show(i){
  const next = layers[idx % 2 ? 0 : 1];
  const prev = layers[idx % 2 ? 1 : 0];
  next.style.backgroundImage = `url('${pic}')`;
  next.animate([{opacity:0},{opacity:1}], {duration:900, easing:'cubic-bezier(.22,1,.36,1)', fill:'both'});
  prev.animate([{opacity:1},{opacity:0}], {duration:900, fill:'both'});
}
```

配合 `@keyframes kenburns { to { transform: scale(1.06) } }`（12s，linear，`alternate`），
一张静态图也能"呼吸"。注意：`prefers-reduced-motion` 下要关掉（见 3.4）。

**(c) 卡片→详情共享元素（FLIP）**

`view.innerHTML=''` 之前记录被点卡片的 `getBoundingClientRect()`，
详情海报渲染后从那个矩形 `transform` 到目标矩形，180ms。
这是"高级感"最廉价的一次性投入，做完整个应用的质感会上一个台阶。

**(d) 全局颗粒 + 暗角**

把 `.hero-grain` 的 data-URI 提到 `body::after`，`opacity:.035`，`mix-blend-mode:overlay`，`pointer-events:none`。
成本近乎为零，暗色界面会立刻"不像网页"。

**(e) 播放器的环境光**

缓冲时的 `.pl-poster` 已经很好了，可以再进一步：`playing` 后保留一层 8% 不透明度的模糊海报在画面四周（`inset:-12%`），
形成电视上常见的 bias lighting。不需要采样视频帧，静态海报就够。

### 3.2 交互：焦点系统是亮点，但"另一条路"是断的

**做得好的**

- `focus.js` 的几何最近邻算法（同轴优先 + 跨轴惩罚 + 边界兜底）比很多 TV 端产品认真；
- 鼠标 `pointerover` 同步焦点，遥控器和鼠标共用一套视觉语言；
- 单击 = 播放/暂停（立即响应）、双击 = 全屏（撤销第一下），这个语义设计很成熟（`player.js:633-669`）；
- 播放器 `Esc` 优先退全屏再关播放器，符合直觉。

**断裂点**

| 问题 | 证据 | 影响 |
|---|---|---|
| 卡片是 `<div data-focus>`，**不在 Tab 序列里** | `ui.js:21-33`，全项目 `tabindex` 出现 0 次 | 键盘用户 Tab 只能摸到顶栏，摸不到任何一张卡片 |
| 全站 `outline:none`，只有 `.focused` 有视觉 | `base.css` 大量 `outline:none`；`focus-visible` 全项目仅 1 处 | 用 Tab 走到按钮时**看不到焦点**，等于裸奔 |
| 返回片库不恢复滚动位置 | `main.js:52-54` 强制 `scrollTo(0,0)` | 翻了 5 屏点进详情，返回回到顶部，还要重新滚 |
| 搜索浮层没有焦点陷阱 / `aria-modal` | `index.html:42`，`nav.js:86` | Tab 会跑到浮层背后的页面；读屏软件不知道这是对话框 |
| Esc 关闭搜索后焦点不回触发按钮 | `nav.js:115` | 键盘用户丢失位置 |
| Toast 单实例 | `dom.js:102` | 连续两次操作，前一条直接被覆盖 |
| 无撤销 | 删源 / 取消收藏 | 误触只能重来 |

**建议（一次改完，成本一天）**

```js
// ui.js：卡片从 div 变成真正的链接 + 语义
`<a class="card" href="${open}" data-focus
    aria-label="${esc(name)}${year ? ' ' + year : ''}">…</a>`
```
`<a href>` 天然进 Tab 序列、支持中键新标签页、支持读屏，且原有 `[data-open]` 委托可以保留。

```css
/* base.css：给键盘用户一个明确的焦点环，鼠标用户不受影响 */
:focus-visible{ outline:2px solid var(--accent); outline-offset:3px; border-radius:inherit }
[data-focus]:focus-visible{ outline:2px solid var(--accent); outline-offset:4px }
```

滚动恢复：路由切换时把 `scrollY` 存进 `history.state`，`popstate` 时还原；
或者更简单——`browse` 页面 `destroy()` 时把 `window.scrollY` 存到模块变量，`render()` 后 `requestAnimationFrame` 还原。

### 3.3 动效：曲线统一，但"该停的没停"

- `--ease: cubic-bezier(.22,1,.36,1)` 统一，节奏是舒服的；
- 但首屏同时跑 `.page` 淡入（.34s）+ `heroIn`（.8s）+ `cardIn`（.45s）三层，元素先后到位，观感是"慢半拍"而不是"依次入场"；
- **`prefers-reduced-motion` 只在 CSS 里生效**（`base.css:343`），Hero 的 10 秒 `setInterval` 仍在切内容，用户关了动效还是会被"啪"地换片；
- `.card:hover` 和 `.card.focused` 两套 transform 同时命中（鼠标移入必中 hover，`pointerover` 又加 focused），高度/缩放会互相覆盖，快速滑过时会有轻微抖动；
- `scrollIntoView({behavior:'smooth'})` + `.rail{scroll-behavior:smooth}` 叠加，遥控器连按时会"追不上"焦点。

**建议**

```js
export const reduceMotion = matchMedia('(prefers-reduced-motion: reduce)').matches;
// hero.js 里：if (reduceMotion) 不启动 setInterval，只保留手动翻页
```
并把 hover / focused 合并成一个规则：`.card:hover, .card.focused { … }` 只留 `.focused` 的焦点环。

### 3.4 排版与 10-foot UI

- 这套 UI 明显是给电视/沙发场景设计的，但正文 meta 用了 **11px / 11.5px / 12.5px**（`home.css:246`、`pages.css:36`）；
  3 米外看 11px 基本不可读。建议给 `body[data-tv="1"]` 或宽屏 `@media (min-width:1600px)` 整体把 11→13、13.5→15。
- 字体是可变字重（`font-weight: 400 700`）+ 101 个 Noto 子集，`font-display: swap` 也有，这块做得对；
  但 `font-weight:660/650/620` 在高对比暗色下差异极小，标题层级更多要靠字距和大小，现在混用得有点随意（`.page-title 660` / `.section-title 650` / `.card-title 500`）。
- `--muted:#7c828f` 在 `#07080b` 上对比度约 5.4:1，正文勉强过 AA，但 11px 小字应 ≥ 7:1；建议小字统一提到 `#8f96a3`。
- Hero 那片"文字 ↔ 海报"之间的大块留白（见 `docs/screenshot-home.png`）在 1440 宽下接近 300px，
  画面会显得空；建议 `hero-copy{max-width:min(560px,52vw)}` 或让海报更靠左、更大。

### 3.5 状态设计：骨架有了，但"等待"没有叙事

- 详情页冷启动 **4.5 秒**只有骨架，没有任何"正在问 13 个片源"的进度感知（`detail.js:22-33`）；
- 搜索 3 秒一次性出结果，其实后端是 `deadline` 到点收口，完全可以"先到的源先渲染"；
- 所有错误态都是同一个 `emptyState` + "刷新"按钮——但用户真正需要的是"换线路 / 换片源 / 用磁力"；
- 首页推荐加载时只轮询 2.5s，没有"正在为你挑选"的文案层次。

**建议**：详情页骨架下面加一行 `已连上 7/13 个片源 · 找到 24 条线路`（后端 `search_online` 已有 per-site 结果，加个 SSE 或轮询即可）；
错误态按场景分三档：网络断（检查 NAS）→ 片源全挂（去片源管理）→ 单片无线路（换磁力）。

## 4. 前端功能缺失（对照 NAS 媒体中心的预期）

按"用户会立刻觉得缺"排序：

| # | 缺失 | 说明 | 优先级 |
|---|---|---|---|
| 1 | **本地影库** | 只聚合在线采集站，NAS 硬盘上的电影/剧集无法扫描播放。这是"NAS 媒体中心"的核心场景 | P1 |
| 2 | **字幕** | 无外挂 srt/ass、无字幕搜索、无样式/延迟调节。外语片基本不可用 | P1 |
| 3 | **自动连播下一集** | 播完就停，剧集要手动点。缺少最常见的追剧动作 | P0 |

### 5.1 性能

| 问题 | 位置 | 数据 | 建议 |

| 分类映射盲探 | `catalog.py:127-156` | 30 个 ID × 5 源 ≈ 150 请求，首点 26s | **改用 `ac=list` 一次拿到 `class` 表**（MacCMS 标准接口），1 次请求解决；失败再退回盲探 |

### 5.2 健壮性

- `db.py:99-111` `dbrun` 吞掉所有异常返回 `[]`/`None`：**数据库出问题时页面只显示"没有内容"**，排查只能看 stderr。建议至少 `log()` 一次带 SQL 前 80 字符。
- `qbt.py:124` `QBT` 是全局单例，`CookieJar` 被多线程共享 → 并发请求下可能登录态串味。建议按线程持有或加锁。
- `db()` 每线程一个连接，线程结束不显式 close → 长跑后 fd 缓慢增长。可加 `atexit` 或用连接池。
- `music.local_index()` 在请求线程里同步 `os.walk`（`music.py:170`），2 万首会阻塞整个请求几十秒，且 `_INDEX` 无进度反馈。建议后台线程 + 任务态。
- `proxy.fetch()` 把整段分片 `r.read()` 进内存（`proxy.py:88`），且无大小上限；一个异常大的 m3u8 分片会吃掉内存。建议流式转发 + `Content-Length` 上限。
- `live.check_channels()` 硬编码 `limit=240 / workers=16 / timeout=4`（`live.py:156`），大分组永远测不全。
- `sources` 表没有 `(kind, enabled, pri)` 联合索引，源多了以后每次 `active_sites()` 全表扫（小问题）。

### 5.3 工程化

- **没有任何自动化测试**。`tools/*.mjs` 是手动脚本。至少补：`text.py` 的归一化/画质识别、`cms._parse_play_url` 的 5 种脏格式、`tvbox.clean_json` 的容错——这三个是纯函数，最好测也最容易回归。
- **无 CI**。加一个 GitHub Action：`python -m py_compile` + 纯函数单测 + `eslint --no-eslintrc` 语法检查，10 行 YAML。
- **日志只写 stderr**，无级别、无轮转、无请求耗时。建议一行 JSON 日志 + `logrotate` 或 Docker `--log-opt max-size`。
- **Dockerfile 无 `HEALTHCHECK`、以 root 运行**。加：
  ```dockerfile
  HEALTHCHECK --interval=30s --timeout=3s CMD wget -qO- http://127.0.0.1:8899/api/status || exit 1
  USER nobody
  ```
  并补一个 `/healthz`（只回 `ok`，不查远程源，避免探活把服务拖慢）。
- **重复的 CORS 头**（见 §1），`_serve_file` 的 `extra` 与 `_send` 里各加了一次。
- `static/*.gz` 在 `.gitignore` 里有，但代码里没有任何地方读它——要么实现预压缩，要么删掉这条规则，避免误导。

### 9.5 补充修复：无限滚动重复卡片

**现象**：年份筛选或深度滚动后，同一张卡在网格里出现两次，越往下翻越多。

**根因（三层叠加）**

1. `api.py` 把页号 `min(30, pg)` 夹住：第 31 页请求会静默变成"再取一次第 30 页"，
   客户端于是反复拿到同一批数据；
2. `browse.js` 只按 `more` 判断是否继续，某页全是已见条目时（筛选后很常见）仍继续翻页，
   一直翻到第 30 页；
3. 追加卡片只依赖内存里的 `st.seen`，DOM 层没有兜底；名字/年份的空白差异漏一条就会露出重复。

**修复**

| 层 | 改动 |
|---|---|
| 接口 | `pg > 30` 直接返回 `{items: [], more: false}`，不再夹页号 |
| 状态 | 追加时 `added.length === 0` 或 `items.length === 0` 立即 `more = false` |
| DOM | 卡片带 `data-key`，插入前按 key 再查一遍；渲染前 `paintList` 再收一遍 |
| 加载 | 弃用 IntersectionObserver（sentinel 常驻视口只会触发一次），改为滚动 + 请求结束主动检查 |

**验证**：剧集页滚 3 屏 180 条、切 2026 后 327 条，按 `data-key` 统计重复 **0**，无 console 报错。
